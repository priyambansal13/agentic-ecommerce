# agentic-commerce / backend

**Microservices** for the agentic-commerce marketplace: 12 independently deployable NestJS 12 services,
each with **its own database, Dockerfile, version and CI pipeline**, talking only through Kong (sync) and
Kafka (async, transactional outbox). Includes the **agents service** (LangGraph.js + AG-UI 1.0 + OPA +
hash-chained audit). Architecture: [`../platform/docs`](../platform/docs) — especially `07-microservices.md`.

Each service's `README.md` is its service card (topics, secrets, image) — generated from `package.json` `"ac"` by `pnpm gen sync`.

## Layout

```
services/<name>/   microservice: src/, Dockerfile, README.md (card), .env.example, package.json "ac" metadata
libs/              @ac/contracts + @ac/money (published, versioned with Changesets) · @ac/nest-common + @ac/kafka (internal)
policies/          OPA: agent tool authorization (+ tests) · refund decision tables
evals/<agent>/     agent eval datasets (CI gate)
scripts/           gen.mjs (service / agent / sync) · publish-libs.mjs
```

## Commands

```bash
pnpm install && pnpm build && pnpm test
pnpm dev                                   # all services (infra: node ../platform/scripts/ac.mjs infra up)
pnpm dev --filter @ac/catalog...           # one service (+ its libs)
pnpm gen service <name> [--port N] [--db name|--no-db]
pnpm gen agent <id>
pnpm gen sync                              # regenerate service cards, Dockerfiles, .env.example
pnpm changeset && pnpm libs:version        # version shared libs; `ac libs publish` publishes locally
pnpm policy:test                           # OPA tests
pnpm --filter @ac/agents run evals -- --agent ping
docker build -f services/<name>/Dockerfile -t ac/<name> .
```

Config: `services/<name>/.env` (own `DATABASE_URL` + only its secrets) and `.env` (shared non-secret),
both generated by `ac configure` in the platform repo. Claude Code: `CLAUDE.md`, `.claude/skills`, `.claude/agents`.

## Deployment

Production runs on **k3s on an Oracle Cloud Always Free VM** (platform repo, `deploy/`). Each service is its own
Deployment + Service `<service>` with Secret `svc-<service>` (its own `DATABASE_URL` + declared secrets) and is
reachable only from Kong (`edge`) by NetworkPolicy. CI builds affected services as **linux/arm64** images to
`ghcr.io/<owner>/ac/<service>`; deploy/rollback one service with `ac k8s deploy prod <service> --tag <sha>` /
`ac k8s rollback prod <service>` from the platform repo.
