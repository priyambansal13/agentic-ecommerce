# Add a microservice

Every service is **independently deployable**: own process, container image, database, env, Kafka
consumer groups and version. It talks to others only via Kong/HTTP (sync) and Kafka events (async).

Before you start, confirm the service is justified in `../platform/docs/01-hld.md` §1.2 (service catalog)
and the microservices doc in `../platform/docs/`. If it isn't there, run the `architect` agent / write an
ADR first (platform repo, `architecture-decision` skill).

## 1. Generate
```bash
pnpm gen service <name> --port <41xx> --db <database>   # stateless (e.g. search): --no-db
# or from the workspace: node platform/scripts/ac.mjs new service <name> --port <41xx> --db <database>
```
Creates:
```
services/<name>/
  package.json        # @ac/<name>, "type":"module", "ac": { kind, port, database, owner, publishes, consumes }
  Dockerfile          # multi-stage, pnpm deploy → node:24-alpine, non-root, HEALTHCHECK /health
  README.md           # service card: owner, purpose, API, events, database, SLOs, runbook
  .env.example        # PORT, DATABASE_URL, KAFKA_BROKERS, OIDC_ISSUERS … (no secrets)
  nest-cli.json, tsconfig.json, tsconfig.build.json
  src/main.ts         # bootstrapService(AppModule, { name, port })
  src/app.module.ts   # CoreModule.forService({ name, database: true }) → DB, JWT guard, /health,
                      #   /v1/whoami, idempotency, outbox relay, EventConsumerService
  src/modules/        # one folder per feature: controller → service → repository, entities/, dto/
  src/events/         # consumers
```
Fill in `"ac".owner`, `publishes` and `consumes` in `package.json` — the platform CLI and docs read them.

## 2. Database (database-per-service)
- Database `ac_<database>` owned by role `svc_<database>`; the service connects with its own
  `DATABASE_URL` from `services/<name>/.env` (generated by `ac configure`, gitignored).
- Create it locally (idempotent, also generates the per-service password and Kong route):
  ```bash
  node ../platform/scripts/ac.mjs configure && node ../platform/scripts/ac.mjs infra init
  ```
- The role gets **no** access to any other database. Never read another service's tables — call its
  API or consume its events and keep a local read model.
- Tables come from migrations only (`db-migration` skill). Platform tables (outbox, processed_events,
  idempotency_keys) are created by `@ac/nest-common`.

## 3. Gateway route
`ac infra init` regenerates `../platform/infra/kong/kong.yml` from every `services/*/package.json`
(`/api/<name>` → `<name>:<port>`, strip path, rate limit). Verify:
```bash
curl -s localhost:58000/api/<name>/health
curl -s -H "Authorization: Bearer $(node ../platform/scripts/ac.mjs token)" localhost:58000/api/<name>/v1/whoami
```

## 4. Contracts and events
- DTOs/events the service exposes go in `libs/contracts` (zod) → `api-endpoint` / `domain-event`
  skills. Publishing a changed contract for the frontend → `contracts-release` (platform skill).
- New topic? add it to `../platform/infra/kafka/topics.json` and `TOPICS` in `libs/contracts`.

## 5. Container, CI, deploy
```bash
docker build -f services/<name>/Dockerfile -t ac/<name>:dev .     # from the backend root
docker run --rm --env-file services/<name>/.env -p <port>:<port> ac/<name>:dev
```
- CI (`.github/workflows/ci.yml`) picks it up automatically: affected-only build/test/docker per service.
- Cluster (k3s on Oracle Cloud): from the platform repo run `ac k8s values` (adds its Deployment/Service
  `<name>` + NetworkPolicy from the `ac` metadata), `ac kong --k8s` (route `/api/<name>`), `ac k8s secrets <env>`
  (Secret `svc-<name>` with its own `DATABASE_URL` + declared `ac.secrets`; role/DB added to `ac-db-bootstrap`),
  add its tag to `platform/deploy/envs/<env>.tags.json`, test on `ac k8s local`, then deploy (platform skill
  `k8s-deploy`). Images: `ghcr.io/<owner>/ac/<name>`, linux/arm64.

## 6. Docs (same PR, platform repo)
`../platform/docs/01-hld.md` §1.2 catalog row (port, database, publishes/consumes), `02-lld.md` section
(ER diagram, API table, events), microservices doc service table. Keep the service card README current.

## Checklist
- [ ] Generated with `pnpm gen service`; port unique; ESM `.js` relative imports
- [ ] `ac` metadata complete (owner, database, publishes, consumes)
- [ ] Own database + role; no cross-database access; migrations only
- [ ] `/health` 200 and `/v1/whoami` 401 without token via Kong
- [ ] Docker image builds and runs with only its own `.env`
- [ ] Sync calls to other services have timeouts/retries/breakers (`service-resilience`)
- [ ] Consumers idempotent; events versioned in `@ac/contracts`
- [ ] Service card README + platform docs updated; `ac k8s values` regenerated and tag in `<env>.tags.json` (if deploying)
- [ ] Resource requests/limits sensible for the shared 12 GB node
