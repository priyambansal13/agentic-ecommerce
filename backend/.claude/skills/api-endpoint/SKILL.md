# Add / change a REST endpoint

Rules: RESTful, versioned (`/v1/...`), stateless, JSON, contract-first. Check the endpoint against the
service's API table in `../platform/docs/02-lld.md` first — if it is new, you'll add it there at the end.

## 1. Contract (libs/contracts)
```ts
// libs/contracts/src/order/dto.ts
import { z } from 'zod';
import { MoneySchema } from '../common/money.js';

export const AddCartItemRequest = z.object({
  skuId: z.uuid(),
  qty: z.int().min(1).max(20),
});
export type AddCartItemRequest = z.infer<typeof AddCartItemRequest>;

export const CartResponse = z.object({
  id: z.uuid(),
  items: z.array(z.object({ skuId: z.uuid(), qty: z.int(), priceSnapshot: MoneySchema })),
});
```
- Money fields always `MoneySchema` (`{ amountMinor: bigint-as-string|int, currency }`), never floats.
- Breaking change? Add `/v2` route or a new optional field — never change meaning of an existing field.
- Rebuild: `pnpm turbo run build --filter=@ac/contracts`.

## 2. Controller (thin)
```ts
@Controller({ path: 'cart', version: '1' })
@UseGuards(AuthGuard)                         // from @ac/nest-common
export class CartController {
  constructor(private readonly cart: CartService) {}

  @Post('items')
  @HttpCode(201)
  async add(@Principal() user: PrincipalCtx, @Body(new ZodPipe(AddCartItemRequest)) body: AddCartItemRequest) {
    return CartResponse.parse(await this.cart.addItem(user.sub, body));
  }
}
```
- Validate input with the zod pipe, validate output with `.parse` (catches leaks of internal fields).
- Authorization: role/ownership checks in the service (`buyer`, `seller`, staff roles) — the guard only
  authenticates. Agent calls carry `act` claim; log both `sub` and `act`.

## 3. Service (use case + transaction)
- One transaction per use case (`dataSource.transaction(async (tx) => …)`).
- If state changes → write outbox row in the same `tx` (see `domain-event` skill).
- If it changes a state machine → use the transition table (see `saga-and-state-machine`).

## 4. Idempotency (required for money/stock/order creation)
Apply the interceptor:
```ts
@Post()
@UseInterceptors(IdempotencyInterceptor)   // requires Idempotency-Key header, 422 on hash mismatch
async checkout(...) {}
```
Required on: checkout, reservations, payment intents, refunds, payouts, store credit, any agent-callable
WRITE/MONEY tool endpoint. Internal endpoints (`/internal/...`) also need it — retries happen there too.

## 5. Errors
Use problem+json from the common error filter: `409` stock/state conflicts (include offending ids),
`412` version mismatch on `If-Match`, `422` validation/business rule, `403` ownership. Never return
stack traces.

## 6. Tests
- Unit: service logic with repository fakes (`vitest`).
- Integration: controller + real Postgres via Testcontainers (`services/<svc>/test/*.e2e.ts`) incl.
  idempotent replay (same key twice → same response, one DB effect) and ownership `403`.
- Contract: response parses with the contract schema.

## 7. Docs & gateway
- Add the row to the service's API table in `../platform/docs/02-lld.md`.
- New path prefix? Ensure `../platform/infra/kong/kong.yml (generated by `ac infra init` from service metadata)` routes it. Public endpoint? say so in the table.

## Microservice rules
- **Backwards compatible only**: add fields/endpoints; never remove/rename/retype in place. Breaking change →
  new version path (`/v2/...`) served alongside `/v1` until every consumer (other services, agents tools,
  frontend zones) has moved — coordinate with the platform `cross-repo-change` skill.
- The frontend consumes DTO types from the **published** `@ac/contracts`: after changing contracts run
  `pnpm changeset` (minor for additive) and follow `contracts-release` (platform repo).
- Consumers (other services) get a consumer-driven contract test (Pact or fixture-based) in this repo.
- Calls this endpoint makes to other services follow `service-resilience`.
