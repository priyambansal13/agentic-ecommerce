# user service

Profiles, addresses and **seller accounts with KYC** (GSTIN checksum, PAN↔GSTIN, GST state code, IFSC; PAN masked and bank last-4 only in responses). Credentials, MFA and login live in Keycloak; on KYC approval the service grants the customers-realm `seller` role via the Keycloak Admin API (client `user-service`). Also owns **gated-category approvals** (category list read from catalog `GET /v1/categories`, cached 5 min). APIs: `GET/PUT /v1/sellers/me`, `POST /v1/sellers/me/submit` (buyer, seller) · `GET /v1/sellers/me/categories`, `POST /v1/sellers/me/categories/:category` (seller) · `GET /v1/kyc/queue`, `POST /v1/kyc/:sellerId/decision` (compliance, admin) · `GET /v1/category-approvals/queue`, `POST /v1/category-approvals/:id/decision` (category-team, admin). Events: `user.seller_verified.v1`, `user.category_approved.v1`. State machine: DRAFT → SUBMITTED → VERIFIED | REJECTED | ACTION_REQUIRED (→ SUBMITTED); decisions are version-checked (409) with history in `kyc_history`.
