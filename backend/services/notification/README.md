# notification service

Buyer notifications from `order.events` and `payment.events`: order confirmed, shipped (carrier tracking link), delivered, cancelled (refund note), payment failed, refund issued. Each event becomes one **in-app** row and — when the buyer's email is known (`notifyEmail` on order events, remembered per order in `order_contacts`) — one **email** row; `UNIQUE(event_id, channel)` makes redelivery harmless. The `notifications` table doubles as the email outbox: a sender loop delivers `PENDING` rows over SMTP (`SMTP_URL`, Mailpit locally at http://localhost:58025) with exponential backoff, `FAILED` after 5 attempts. Without `SMTP_URL` notifications are in-app only. Templates (`src/modules/notifications/templates.ts`) escape all seller/buyer text and format ₹ in en-IN.
