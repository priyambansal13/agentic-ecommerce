# order service

Cart, checkout saga orchestration and order lifecycle with per-seller sub-orders. **Cart** (`GET/POST/PATCH/DELETE /v1/cart…`): signed-in customers by token sub, guests by `X-Cart-Session` (32 hex, 7-day sliding TTL) — both in this service's database (`cart_items`, `guest_cart_items`; Redis was dropped because an ioredis peer forks TypeORM); `POST /v1/cart/merge` after sign-in; lines are re-priced live from catalog (`GET /offers`) and inventory (`GET /stock`) and degrade to `UNAVAILABLE` (no checkout) when either is down; shipping ₹40 per seller below ₹499. **Checkout** `POST /v1/checkout` (buyer, `Idempotency-Key`): re-price (409 `TOTAL_CHANGED`/`OFFER_UNAVAILABLE`) → `ORDER(CREATED)` + seller orders + lines + `order.created.v1` in one tx → fraud score (300 ms, timeout ⇒ REVIEW; BLOCK ⇒ REJECTED 422) → inventory reservation (409 `OUT_OF_STOCK`) → payment session (failure ⇒ release + REJECTED 503) → `PENDING_PAYMENT`, cart cleared. **Lifecycle**: `payment.succeeded.v1` ⇒ PAID ⇒ CONFIRMED + `order.confirmed.v1` (REVIEW orders are confirmed but keep `risk_decision = REVIEW` for the analyst; a payment that arrives after the order closed emits `order.cancelled.v1` with `refundRequired`); `payment.failed.v1` ⇒ PAYMENT_FAILED, `inventory.reservation_released.v1` (EXPIRED) ⇒ CANCELLED/PAYMENT_EXPIRED — both restore the cart; `POST /v1/orders/:id/cancel` (before shipping; refund owed when paid); seller `GET /v1/sellers/me/orders?status=`, `POST /v1/seller-orders/:id/ship` ⇒ SHIPPED/PARTIALLY_SHIPPED + `order.shipped.v1`; demo carrier delivers after `DEMO_DELIVERY_MINUTES` (3) ⇒ `order.delivered.v1`. All transitions go through a transition table + version check and are recorded in `order_events`; `GET /v1/orders/:id|ORD-no` shows the timeline. Dashboards (`/v1/dashboard/buyer|seller|platform`) and `GET /v1/orders/mine` map the new statuses onto their narrower enum (CREATED/REJECTED hidden, PAYMENT_FAILED → CANCELLED, PARTIALLY_SHIPPED → SHIPPED).
