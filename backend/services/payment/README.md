# payment service

Payments for checkout, with **gateway webhooks as the source of truth**. Providers behind one interface: **testpay** (built-in TEST gateway, always on, no real money — test cards `4242 4242 4242 4242` succeeds, `4000 0000 0000 0002` declined, `4000 0000 0000 9995` insufficient funds) and **Stripe** test mode (enabled only when `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` and `STRIPE_PUBLISHABLE_KEY` are set). APIs: service `POST /v1/internal/payments` (idempotent on orderId → session) and `POST /v1/internal/refunds` (idempotent on refundCaseId, Σ refunds ≤ captured) — role `service` · buyer `GET /v1/payments/:id`, `POST /v1/payments/:id/testpay` (202; only brand + last 4 stored) · public `POST /v1/webhooks/testpay|stripe` (HMAC-SHA256 over the raw body, `t=…,v1=…`, 5-minute tolerance; inbox `webhook_events` dedupes on the provider event id; replays return 200 no-op). On success, in one transaction: payment `SUCCEEDED`, balanced CAPTURE (Dr `gateway:clearing`, Cr `seller:<id>:payable` per seller + `platform:shipping`), `order_fees` stamped with the active fee-schedule version + FEE transactions, outbox `payment.succeeded.v1`; failure → `payment.failed.v1`. A capture that arrives before `order.created.v1` is parked in `suspense:unallocated` and allocated when the lines arrive. Consumes `order.created.v1` (order lines read model) and `order.cancelled.v1` (paid → full refund + fee reversal + `payment.refunded.v1`; unpaid → session `CANCELED`; a success arriving after cancellation is refunded automatically). Sweeper cancels expired sessions every 30 s.
