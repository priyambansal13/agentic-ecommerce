# Add a micro-frontend zone

Zones are independently built and deployed Next.js 16 apps. The **shell** (port 3300) owns `/` and the
global chrome and rewrites each zone's basePath to that zone. Current zones: storefront `/shop` 3301,
account `/account` 3302, seller `/seller` 3303, admin `/admin` 3304. Read the micro-frontends doc in
`../platform/docs/` before splitting — a zone should map to a domain/team, not a single page.

## 1. Generate
```bash
pnpm gen zone <name> --base /<path> [--port 33xx]
# or from the workspace: node platform/scripts/ac.mjs new zone <name> --base /<path>
```
Creates `apps/<name>/` and registers it in `zones.json`:
```
apps/<name>/
  package.json        # @ac/zone-<name>, "ac": { kind: "zone", port, basePath, owner }
  next.config.ts      # basePath: '/<path>', output: 'standalone'
  Dockerfile          # Next standalone image (node:24-alpine, non-root)
  .env.local          # generated by `ac configure` (gitignored)
  src/app/layout.tsx  # <SiteHeader current="<basePath>"/> from @ac/ui + @ac/ui/tokens.css
  src/app/page.tsx
  src/app/api/agents/[agentId]/run/route.ts   # export const POST = agentRoute();
```
`zones.json` drives the shell's rewrites (`/<path>` and `/<path>/:path*` → `http://localhost:<port>` locally,
zone service URL in the cloud) and the header nav.

## 2. Rules for zone code
- The zone owns its routes, data fetching (server-side via `kongFetch` from `@ac/bff`) and agent renderers.
- **No imports from another zone.** Shared code only through versioned packages (`@ac/ui`,
  `@ac/agui-kit`, `@ac/agent-widget`, `@ac/bff`, published `@ac/contracts`, `@ac/money`).
- Links to another zone: `<ZoneLink href="/account/orders">` (hard navigation). `next/link` only for
  routes inside this zone (paths are relative to basePath: `href="/orders"` → `/account/orders`).
- Assets/fonts: rely on basePath (`/<path>/_next/...`); never hard-code `/_next`.
- No access tokens or service URLs in client components; env vars without `NEXT_PUBLIC_` stay server-side.

## 3. Run & verify
```bash
pnpm install
pnpm dev --filter @ac/zone-<name> --filter @ac/zone-shell
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3300/<path>       # through the shell
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:<port>/<path>     # zone directly
docker build -f apps/<name>/Dockerfile -t ac/zone-<name> .
```

## 4. Platform + docs
- Keycloak redirect URIs already cover `http://localhost:3300/*` (zones are served via the shell).
- Cluster (k3s): platform `ac k8s values` adds Deployment/Service `zone-<name>` (+ NetworkPolicy: only the
  shell may call it); rebuild the **shell** image — rewrites are build-time, default
  `ZONE_<NAME>_URL=http://zone-<name>:<port>`; `ac k8s secrets <env>` creates Secret `zone-<name>`; add
  tags for the zone and the shell to `platform/deploy/envs/<env>.tags.json`; see platform skill `k8s-deploy`.
- Update the micro-frontends doc (zone table: path, port, owner, agents) in `../platform/docs/`.

## Checklist
- [ ] Generated with `pnpm gen zone`; basePath + port unique; listed in `zones.json`
- [ ] Reachable through the shell and directly; assets load under basePath
- [ ] Cross-zone links use `ZoneLink`; no cross-zone imports
- [ ] BFF agent route present if the zone hosts agent UI
- [ ] Docker image builds; CI picks it up
- [ ] Docs zone table updated; cluster values regenerated + shell rebuilt if deploying
